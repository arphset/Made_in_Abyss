## 2. Время отклика (задача 7.1, R.01.01)

Запуск: `docker exec qualityjpg_app python tests/benchmark.py`. Набор: 11–12 фото из `test_jpegs/`
и два синтетических файла ~5 и ~10 МБ (шум, худший случай для сжатия). «Первичный отчёт» — сохранение,
CV-анализ и оценка; «Всего» — вместе с рекомендациями Ollama.

### Выполненные оптимизации

| # | Проблема | Решение |
|---|---|---|
| 1 | LLM переписывала все 11 метрик в ответе (~150 лишних токенов на CPU) | Блок метрик подставляется кодом, модель генерирует только оценку и советы; `max_tokens=350` |
| 2 | Рекомендации считались **до** показа отчёта: пользователь ждал всё время | Первичный отчёт выводится сразу, рекомендации — потоком (`st.write_stream`) |
| 3 | YOLO загружалась с диска при каждом анализе | Модель загружается один раз на процесс (с блокировкой для параллельных сессий) |
| 4 | Холодный старт: первая проверка после запуска до 26 с | Фоновый прогрев YOLO и Ollama (`keep_alive=60m`) при старте сервера |
| 5 | Веса YOLO скачивались из интернета при каждом пересоздании контейнера | Путь к весам в смонтированной папке (`YOLO_WEIGHTS`) |
| 6 | Оригинал перекодировался через OpenCV | Файл сохраняется байт-в-байт |
| 7 | HTTP-клиент Ollama создавался на каждый запрос | Один клиент на процесс |

### Контроль в эксплуатации
- Время каждой проверки (CV, LLM, всего) сохраняется в БД (`analysis_results.cv_time_ms / llm_time_ms / total_time_ms`).
- Пользователь видит время обработки под отчётом; при превышении 30 с выводится предупреждение.
- В админ-панели — блок «Время отклика»: среднее, 95-й перцентиль, максимум, число превышений и график с линией норматива.
